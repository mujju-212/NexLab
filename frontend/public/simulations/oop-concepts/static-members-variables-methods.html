Theory: Static Members

Static members (variables and methods) belong to the class itself, not to any one object. There is exactly one copy of a static variable in memory, shared by every instance — change it through any object (or the class name) and every instance sees the update. This contrasts with instance members, where each object gets its own independent copy.

Java

Uses the static keyword. Accessed via ClassName.member — a single slot in the class's memory area, not the heap-per-object area.

Python

A variable assigned directly in the class body (not inside __init__) is a class variable — shared unless an instance shadows it with its own attribute of the same name.

C++

Uses static inside the class plus an out-of-class definition. Accessed via ClassName::member.

Static vs. Instance Members — Multi-Language

Java

class Counter {
  static int count = 0;   // shared
  int serial;              // per-instance
  Counter() {
    count++;
    serial = count;
  }
}
Counter c1 = new Counter();
Counter c2 = new Counter();
Counter.count; // shared by both

Python

class Counter:
    count = 0   # class (static) variable

    def __init__(self):
        Counter.count += 1
        self.serial = Counter.count  # instance

c1 = Counter()
c2 = Counter()
Counter.count  # shared by both

C++

class Counter {
  public:
    static int count;  // shared
    int serial;          // per-instance
    Counter() { serial = ++count; }
};
int Counter::count = 0;
Counter c1; Counter c2;
Counter::count; // shared by both

The core idea to prove in the simulator

Create several instances. Each has its own independent serial attribute (an instance variable) — but there is only ONE count in memory. Incrementing it from any instance's button must update the value displayed on every instance's card simultaneously, because they are all reading the exact same shared storage location.

Simulator Procedure

  1. Open the Simulation tab and select a language pill — Java, Python, or C++.
  2. Note the single Static Memory panel at the top — it shows Counter.count, which exists in exactly one place in memory.
  3. Click Create New Instance multiple times. Each click renders a new instance card with its own independent serial instance attribute.
  4. On any one instance card, click that card's Increment Static (count++) button.
  5. Verify that every instance card's static-count readout updates to the same new value at once — not just the card you clicked — while each card's own serial stays exactly as it was.
  6. This proves the pedagogical point: static members are shared across all instances; instance members are independent per object.
  7. Click Reset to clear all instances and the static counter and start again.
