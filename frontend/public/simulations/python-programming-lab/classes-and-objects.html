Theory: Classes & Objects

A class is a blueprint that defines the structure and behavior of a category of things. An object (or instance) is a concrete allocation in memory created from that blueprint — each object gets its own independent copy of instance attributes.

Class Definition class Name:

Defined with the class keyword: class Car: pass. No object exists yet — this only registers the blueprint.

Instantiation obj = ClassName()

Calling the class name with parentheses allocates a new object on the heap: c1 = Car().

Attributes obj.attribute

Attributes can be dynamically assigned on an instance using dot notation: c1.color = "Red".

Common Pitfalls

  • Each object has independent attributes. Setting s1.name does not affect s2.name — they're separate heap allocations, even though both came from the same class.
  • Attributes assigned outside __init__ only exist on objects where that line actually ran — forgetting to set one leads to AttributeError on other instances.
  • Class attributes vs instance attributes: a value assigned directly inside the class body (not inside a method) is shared by all instances until an instance overrides it — a frequent source of subtle bugs with mutable defaults like lists.
  • Printing an object directly (e.g. print(s1)) shows its memory address by default (<__main__.Student object at 0x...>) unless the class defines __str__.
