Theory: Python Data Types & Mutability

Every value in Python has a specific data type that dictates what it can store, what operations it supports, and whether it can be modified in place (mutable) or not (immutable). Python uses dynamic typing — a variable's type is inferred automatically at runtime, and can change if reassigned.

Numeric Types Immutable

int (whole numbers, e.g. 42), float (decimals, e.g. 3.14159), complex (3 + 4j).

Strings (str) Immutable

Ordered sequence of characters: "Hello World". Supports indexing, slicing, concatenation.

Lists (list) Mutable

Ordered, mutable sequence: [10, 20, 30]. Elements can be updated, appended, or removed dynamically.

Tuples (tuple) Immutable

Ordered, read-only sequence: (10, 20, 30). Item assignment raises TypeError.

Dictionaries (dict) Mutable

Key-value mapping: {"name": "Alice", "age": 20}. O(1) average lookup by key.

Sets (set) Mutable

Unordered collection of unique items: {1, 2, 3}. Duplicates are automatically discarded.

Common Pitfalls

  • Mutable default arguments: a list/dict used as a default function parameter is shared across every call that doesn't override it — a classic beginner bug.
  • Tuples of one element need a trailing comma: (5) is just the int 5, but (5,) is a 1-element tuple.
  • Two variables pointing to the same mutable object (e.g. b = a where a is a list) share the underlying data — mutating one mutates the other. Use a.copy() to avoid this.
  • Dictionary keys must be hashable (immutable) — you can use a tuple as a key, but never a list.
