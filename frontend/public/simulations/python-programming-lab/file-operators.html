Theory: Python File Handling

File handling lets data persist on non-volatile secondary storage (disk) instead of disappearing when the program ends. Python's built-in open() function is the gateway to reading and writing external files.

open() & Modes Modes

'r' read, 'w' write/overwrite, 'a' append, 'x' exclusive create.

read() & write() I/O Streams

f.write("text") writes to the file buffer; f.read() loads the entire content into memory.

with Context Manager Auto-Close

with open(...) as f: automatically flushes and closes the file when the block exits — even on error.

ModeBehaviorIf File Doesn't Exist
'r'Read only, pointer at startRaises FileNotFoundError
'w'Write; truncates/overwrites existing contentCreates a new file
'a'Write; pointer at end, appends without erasingCreates a new file
'x'Exclusive create; fails if file already existsCreates a new file

Common Pitfalls

  • Forgetting to close a file can leave data unflushed in the buffer and never actually written to disk — always prefer with open(...) as f: over manual open()/close().
  • Opening in 'w' mode destroys existing content immediately — even before you write anything. If you meant to keep the old data, you wanted 'a'.
  • Reading a file twice without resetting the pointer gives an empty string the second time — the read cursor is already at the end. Use f.seek(0) to rewind.
  • f.read() loads the ENTIRE file into memory — for huge files, iterate line-by-line instead (for line in f:).
