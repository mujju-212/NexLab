Theory: Minimax & Alpha-Beta Pruning

Minimax is the foundational algorithm for two-player, zero-sum, perfect-information games (Tic-Tac-Toe, Chess, Connect 4). One player (MAX) tries to maximise the final score; the other (MIN) tries to minimise it. The algorithm recursively computes the game-theoretic value of every node, assuming both players play optimally.

minimax(node, isMaximizing):
  if node is a leaf: return node.staticValue
  if isMaximizing:
    return max( minimax(child, False) for child in node.children )
  else:
    return min( minimax(child, True) for child in node.children )

Values are computed bottom-up: leaves have known static values, and every internal node's value is derived only after ALL of its children's values are known (post-order recursion). MAX nodes pick the largest child value; MIN nodes pick the smallest.

Alpha-Beta Pruning

Minimax alone visits every leaf. Alpha-Beta Pruning is an optimisation that computes the exact same result while skipping branches that can be proven irrelevant. It tracks two bounds while recursing: α (the best value MAX can already guarantee) and β (the best value MIN can already guarantee). The instant α ≥ β at some node, the rest of that node's children are pruned — skipped entirely — because a rational opponent higher up the tree would never let play reach them.

Worked Micro-Example

A MIN node has already evaluated its first child and found value 4, so β=4 for its remaining children. Its second child is a MAX node currently being explored; that MAX node's FIRST leaf already returns 8, making α=8 locally. Since α(8) ≥ β(4), the MAX node can immediately stop — it already found something ≥ 8, but the MIN node above will never accept anything ≥ 4 anyway, so any further leaves under this MAX node are provably irrelevant and get skipped.

MIN(β=4) → MAX(α starts at −∞, β=4) → leaf=8 → α=max(−∞,8)=8 → α(8) ≥ β(4) → PRUNE remaining leaves of this MAX node

Plain MinimaxMinimax with Alpha-Beta Pruning
Visits every single leaf in the tree — O(bd) nodes.Skips provably-irrelevant subtrees — with a good move ordering, can approach O(bd/2).
Returns the exact game-theoretic value.Returns the EXACT SAME value — pruning never changes the answer, it only skips work that couldn't change it.
Simple to implement, easy to reason about.Same recursion plus two threaded bounds (α, β) and one cutoff check per node.

Simulator Procedure

  1. Open the Simulation tab. A fixed game tree (3 plies deep, root MAX) is drawn with its 12 leaf values.
  2. Toggle Alpha-Beta Pruning ON or OFF before running — this changes what the algorithm actually does, not just what's displayed.
  3. Click Start to compute the full evaluation trace (recursive, post-order) for the current tree and pruning setting.
  4. Click Step Execution to move through the recursive evaluation one visit at a time — the node currently being visited is highlighted, and backpropagated values appear on internal nodes as soon as they're known.
  5. Or click Run All to animate the entire evaluation automatically.
  6. With pruning ON, skipped subtrees are greyed out and struck through — compare the "Nodes Visited" counter with pruning ON vs OFF using the same tree.
  7. Click Reset to clear the trace and try again, or switch Quick Presets to load a different tree.
