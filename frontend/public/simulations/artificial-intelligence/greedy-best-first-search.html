Theory: Greedy Best-First Search

Greedy Best-First Search (GBFS) is an informed search algorithm: it uses a heuristic function h(n) — an estimate of how close node n is to the goal — to decide which node to expand next. It always expands the node in the open list (frontier) with the lowest h(n), completely ignoring how far it has already travelled to reach that node.

h(n) = √((n.x − goal.x)² + (n.y − goal.y)²)  // straight-line (Euclidean) distance to the goal

The open list only ever contains actual neighbours of nodes that have already been expanded (plus the start node initially) — it is NOT pre-loaded with every node in the graph. Each expansion: pop the lowest-h node from open, mark it expanded, and if it's not the goal, add its not-yet-visited neighbours to open (recording a parent pointer for path reconstruction). The search stops immediately the moment the goal is popped — expanding further would be wasted work.

Worked Micro-Example

Start S has two neighbours, A (h=8.5) and B (h=8.2, slightly closer to goal "as the crow flies"). GBFS greedily expands B first — even though this graph's edges might make the route through A shorter in practice, GBFS has no way to know that; it only trusts the straight-line estimate.

open=[A(8.5),B(8.2)] → pop B (lowest h) → expand B's neighbours → open=[A(8.5), D(5.8), E(3.2)] → pop E (lowest h) → ... → pop Goal → STOP

This is exactly why GBFS is not guaranteed optimal: it can be lured down a path that "looks close" by straight-line distance but is actually longer in real graph distance, while never reconsidering the path through A once a lower-h option exists.

Simulator Procedure

  1. Open the Simulation tab. The graph is drawn with each node's real 2D coordinates; pick a Quick Preset to choose the goal node (h(n) is recomputed live from coordinates).
  2. Click Start to place the start node in the open list.
  3. Click Step Execution — each step pops the LOWEST-h node from the open list, expands it, and adds its unvisited neighbours (with their computed h values) to the open list.
  4. Watch the Open List panel sort itself by h(n) live, and the graph highlight the node being expanded.
  5. Or click Run All to animate the full search automatically. It stops the instant the goal is popped — no further expansion happens.
  6. The final path is reconstructed via parent pointers and highlighted in blue on the graph, and printed in the terminal.
  7. Click Reset to try again.
