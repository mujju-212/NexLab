Theory: Complex Data Types in Python

Beyond scalar primitives (int, float, str), Python ships with three built-in composite data structures that hold collections of values: set (unordered, unique items), dict (key → value mapping), and tuple (ordered, immutable sequence). Choosing the right one is a core design decision in any Python program.

set

Unordered collection with no duplicate elements — inserting a value already present is a no-op. Supports set algebra: union |, intersection &, difference -, symmetric difference ^.

dict

Associative array mapping unique, hashable keys to values with average O(1) lookup. Core methods: .keys(), .values(), .items(), .update(), .get().

tuple ↔ list

Tuples are immutable and 0-indexed. To "modify" one, cast to a mutable list with list(t), edit it, then cast back with tuple(l) — this creates a brand new tuple object.

Common Pitfalls

  • {} creates an empty dict, not an empty set — use set() for an empty set.
  • A single-element tuple needs a trailing comma: (5,) — without it, (5) is just the integer 5.
  • Dictionary keys must be hashable (immutable) — a list cannot be a key, but a tuple can.
  • Never assume set or dict iteration order matches insertion order in older Python versions (guaranteed for dict since 3.7, sets remain unordered).

Patterns Covered in This Lab

Set Algebra — building sets, deduplication, and computing a union with |.
Dictionary Update — reading keys and merging new key-value pairs in place.
Tuple/List Casting — round-tripping an immutable tuple through a mutable list to "modify" it.
