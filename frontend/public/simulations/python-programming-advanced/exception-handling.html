Theory: Exception Handling in Python

An exception is an event that occurs during execution which interrupts the normal flow of a program's instructions. Python handles runtime errors gracefully using the try-except block construct, preventing sudden script crashes and allowing recovery logic to run instead.

try ... except

Code that might raise a runtime error is placed inside try. If an error occurs, execution immediately jumps to the matching except block.

else & finally

else runs only if NO exception occurred in try. finally runs ALWAYS, regardless of errors — ideal for resource cleanup.

raise Exception

Developers can explicitly trigger errors with raise (e.g. raise ValueError("Invalid input")) to enforce business-logic validation.

ClauseRuns when...
exceptAn exception matching its type was raised in try
elseThe try block completed with NO exception
finallyALWAYS — whether an exception occurred, was handled, or not

Common Standard Exception Types

  • ZeroDivisionError: raised when dividing a number by zero (10 / 0).
  • ValueError: raised when a function receives an argument of the right type but an inappropriate value (int("abc")).
  • TypeError: raised when an operation is performed on an inappropriate data type.
  • KeyError / IndexError: raised for a missing dictionary key or an out-of-range sequence index.

Common Pitfalls

  • A bare except: catches every exception including KeyboardInterrupt — always catch a specific exception type when possible.
  • finally runs even if the try block returns or the exception was never caught — don't rely on code after the try/except to always execute cleanup.
  • An unhandled raise crashes the program — wrap risky calls with try/except if the caller shouldn't crash on invalid input.
  • else is easy to forget — code placed directly after except (outside try) runs regardless of success/failure, unlike a true else clause.
