Theory: Comparison-Based Sorting

Sorting rearranges elements into a defined order (typically ascending) using pairwise comparisons. The four algorithms in this lab represent the classic tradeoff space: simple-but-quadratic vs. divide-and-conquer O(n log n), and in-place vs. needing auxiliary memory.

Bubble Sort

Repeatedly steps through the array, swapping adjacent elements that are out of order. Each full pass "bubbles" the largest remaining value to its final position.

Merge Sort

Divide-and-conquer: recursively splits the array in half, sorts each half, then merges the two sorted halves in linear time. Guaranteed O(n log n) regardless of input.

Heap Sort

Builds a max-heap from the array, then repeatedly swaps the root (maximum) with the last unsorted element and re-heapifies. In-place and guaranteed O(n log n), but not stable.

Quick Sort

Divide-and-conquer: picks a pivot, partitions the array so smaller elements land left and larger land right, then recurses on each side. Fast in practice, but a poor pivot choice degrades it to O(n²).

Common pitfall: "Stable" doesn't mean "fast" — it means equal-valued elements keep their original relative order after sorting. This matters when sorting records by one field while wanting a previous sort (e.g. by name) to still hold as a tiebreaker.

Simulator Procedure

  1. Open the Simulation tab and choose an algorithm from the dropdown, or click a Quick Preset dataset (Random, Nearly Sorted, Reverse Sorted, Many Duplicates).
  2. Adjust the Speed slider — higher is faster.
  3. Click Start Sort to animate. Bars being compared turn amber; a bar being written into its sorted position turns emerald.
  4. Watch the live Comparisons and Writes counters — this is a concrete way to see why O(n²) algorithms do far more work than O(n log n) ones on the same data.
  5. Click Randomize at any time to generate a fresh dataset.
